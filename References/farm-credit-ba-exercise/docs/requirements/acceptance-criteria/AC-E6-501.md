# AC-E6-501 Generate Post-Trade Reports

## Acceptance Criteria

### AC-E6-501-01 — Authorize Report Generation

**Given** a user requests generation of a post-trade report,  
**When** the request is evaluated,  
**Then** the system must verify that the user is authorized to generate the selected report type.

### AC-E6-501-02 — Verify Reporting Eligibility

**Given** an issuance or reporting population is selected,  
**When** report generation begins,  
**Then** the system must verify that the included activity has completed settlement or is otherwise authorized for reporting.

### AC-E6-501-03 — Select a Valid Report Definition

**Given** an authorized user selects a report type,  
**When** the system prepares to generate the report,  
**Then** the system must identify an active and valid report definition for that report type.

### AC-E6-501-04 — Retrieve Authoritative Source Information

**Given** a valid reporting population and report definition,  
**When** source information is collected,  
**Then** the system must retrieve finalized transaction, execution, allocation, confirmation, and settlement information from authoritative records.

### AC-E6-501-05 — Detect Missing Source Information

**Given** report generation requires defined source fields,  
**When** one or more required source values are unavailable or incomplete,  
**Then** the system must identify the missing information and must not represent the report as complete.

### AC-E6-501-06 — Apply Report Mappings and Calculations

**Given** the required source information is available,  
**When** the report is generated,  
**Then** the system must apply the approved field mappings, calculations, totals, and summaries defined for the selected report type.

### AC-E6-501-07 — Validate Required Report Fields

**Given** report content has been assembled,  
**When** completeness validation is performed,  
**Then** the system must verify that all required report fields are populated or explicitly handled according to the report definition.

### AC-E6-501-08 — Validate Totals and Internal Consistency

**Given** a report contains calculated values, totals, and transaction details,  
**When** report validation is performed,  
**Then** the system must verify that the values are internally consistent and satisfy the applicable validation rules.

### AC-E6-501-09 — Block Incomplete or Invalid Reports

**Given** required fields, calculations, or internal consistency checks fail,  
**When** generation is completed,  
**Then** the report must not be marked ready for review, approved, or final.

### AC-E6-501-10 — Record Validation Failures

**Given** report validation fails,  
**When** the failure is detected,  
**Then** the system must record the failed validation, affected field or calculation, date and time, and applicable report version or generation attempt.

### AC-E6-501-11 — Create a Unique Report Version

**Given** report generation completes successfully,  
**When** the report is created,  
**Then** the system must assign a unique and traceable report version.

### AC-E6-501-12 — Prevent Indistinguishable Duplicate Reports

**Given** an equivalent report already exists for the same reporting population and report definition,  
**When** a duplicate generation request is submitted,  
**Then** the system must identify the existing report and prevent creation of an indistinguishable duplicate unless authorized regeneration is requested.

### AC-E6-501-13 — Preserve Regeneration History

**Given** an authorized report is regenerated,  
**When** the new report version is created,  
**Then** the system must preserve the prior report version and record the relationship between the versions.

### AC-E6-501-14 — Record Report-Generation Metadata

**Given** a report version is created,  
**When** generation is recorded,  
**Then** the system must retain the report type, generation date and time, generating user or process, reporting population, report definition, and version identifier.

### AC-E6-501-15 — Associate the Report with Source Records

**Given** a report has been generated,  
**When** the report version is stored,  
**Then** the system must associate it with the underlying issuance, execution, allocation, confirmation, and settlement records used to produce it.

### AC-E6-501-16 — Make the Report Available for Review

**Given** a report passes required generation validations,  
**When** generation completes,  
**Then** the system must make the report available to authorized users for review without representing it as approved or published.

### AC-E6-501-17 — Preserve Audit Traceability

**Given** a report-generation event occurs,  
**When** the event is recorded,  
**Then** the system must preserve sufficient audit information to determine who or what initiated generation, which source records were used, what validations were performed, and what outcome occurred.
