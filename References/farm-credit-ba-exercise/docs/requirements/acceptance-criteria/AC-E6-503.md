# AC-E6-503 Deliver Compliance and Regulatory Reports

## Acceptance Criteria

### AC-E6-503-01 — Authorize External Report Delivery

**Given** a user requests delivery of a compliance or regulatory report,  
**When** the request is evaluated,  
**Then** the system must verify that the user is authorized to deliver the selected report type.

### AC-E6-503-02 — Require an Approved Report Version

**Given** a report is selected for delivery,  
**When** delivery begins,  
**Then** the system must verify that the selected report version is approved for external distribution.

### AC-E6-503-03 — Identify the Reporting Obligation

**Given** an approved report is selected,  
**When** the delivery request is prepared,  
**Then** the system must identify the applicable reporting obligation, recipient, deadline, and required delivery channel.

### AC-E6-503-04 — Validate Recipient Information

**Given** a designated recipient has been identified,  
**When** delivery is requested,  
**Then** the system must verify that the recipient information is complete, current, and authorized for the reporting obligation.

### AC-E6-503-05 — Validate the Delivery Deadline

**Given** a reporting obligation has a required submission deadline,  
**When** delivery is initiated,  
**Then** the system must determine whether the delivery is on time, late, or at risk of being late.

### AC-E6-503-06 — Use an Approved Delivery Channel

**Given** an approved report and valid recipient information,  
**When** the report is delivered,  
**Then** the system must use the approved delivery channel for the applicable reporting obligation.

### AC-E6-503-07 — Deliver the Approved Report Version

**Given** all delivery checks pass,  
**When** delivery occurs,  
**Then** the system must transmit the selected approved report version to the designated recipient.

### AC-E6-503-08 — Preserve Report Integrity

**Given** a report is delivered externally,  
**When** the delivery package is created,  
**Then** the delivered content must match the approved report version without unauthorized modification.

### AC-E6-503-09 — Record Successful Delivery

**Given** report delivery succeeds,  
**When** the delivery event is recorded,  
**Then** the system must retain the report version, reporting obligation, recipient, delivery date and time, delivery channel, user or process, and successful outcome.

### AC-E6-503-10 — Preserve Submission Evidence

**Given** a delivery channel returns an acknowledgement, receipt, confirmation, or reference identifier,  
**When** delivery completes,  
**Then** the system must associate that evidence with the delivery event.

### AC-E6-503-11 — Record Failed Delivery

**Given** a delivery attempt fails,  
**When** the failure is detected,  
**Then** the system must retain the report version, recipient, attempted date and time, delivery channel, failure reason, and responsible user or process.

### AC-E6-503-12 — Record Rejected Submission

**Given** the recipient or delivery channel rejects a submitted report,  
**When** the rejection is received,  
**Then** the system must record the rejection reason, date and time, report version, and applicable submission reference.

### AC-E6-503-13 — Prevent Delivery of Superseded Reports

**Given** a newer approved report version exists,  
**When** a user attempts to deliver an older or superseded version,  
**Then** the system must block delivery unless an authorized exception applies.

### AC-E6-503-14 — Preserve Resubmission History

**Given** an authorized resubmission occurs,  
**When** the report is delivered again,  
**Then** the system must preserve the prior delivery event and record the new event separately.

### AC-E6-503-15 — Display Current Delivery Status

**Given** one or more delivery attempts exist,  
**When** an authorized user reviews the report,  
**Then** the system must display the current delivery status and relevant submission history.

### AC-E6-503-16 — Preserve Audit Traceability

**Given** a compliance or regulatory delivery event occurs,  
**When** the event is recorded,  
**Then** the system must preserve sufficient audit information to determine who or what initiated delivery, which report version was used, who received it, which obligation and channel applied, and what outcome occurred.
