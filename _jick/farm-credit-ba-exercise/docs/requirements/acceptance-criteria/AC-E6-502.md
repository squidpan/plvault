# AC-E6-502 Publish Reports to Internal Stakeholders

## Acceptance Criteria

### AC-E6-502-01 — Authorize Report Publication

**Given** a user requests publication of a post-trade report,  
**When** the request is evaluated,  
**Then** the system must verify that the user is authorized to publish the selected report type.

### AC-E6-502-02 — Require an Approved Report Version

**Given** a report is selected for internal publication,  
**When** publication begins,  
**Then** the system must verify that the selected report version is approved for distribution.

### AC-E6-502-03 — Prevent Publication of Superseded Reports

**Given** a newer approved report version exists,  
**When** a user attempts to publish an older or superseded version,  
**Then** the system must block publication unless an authorized exception applies.

### AC-E6-502-04 — Identify Authorized Internal Recipients

**Given** an approved report is ready for publication,  
**When** the recipient population is determined,  
**Then** the system must identify only internal recipients authorized for that report type.

### AC-E6-502-05 — Validate Recipient Access

**Given** internal recipients have been identified,  
**When** publication is requested,  
**Then** the system must verify that each recipient is permitted to access the selected report.

### AC-E6-502-06 — Prevent Unauthorized Distribution

**Given** one or more recipients are not authorized,  
**When** publication is attempted,  
**Then** the system must block distribution to those recipients and record the authorization failure.

### AC-E6-502-07 — Use an Approved Internal Channel

**Given** an approved report and authorized recipients,  
**When** the report is published,  
**Then** the system must use an approved internal publication or delivery channel.

### AC-E6-502-08 — Publish the Selected Report Version

**Given** all publication checks pass,  
**When** publication occurs,  
**Then** the system must make the selected approved report version available to the authorized internal recipients.

### AC-E6-502-09 — Preserve Report Integrity

**Given** a report is published,  
**When** recipients access the report,  
**Then** the published content must match the approved report version without unauthorized modification.

### AC-E6-502-10 — Record Successful Publication

**Given** report publication succeeds,  
**When** the publication event is recorded,  
**Then** the system must retain the report version, publication date and time, publishing user or process, recipients, channel, and successful outcome.

### AC-E6-502-11 — Record Failed Publication

**Given** a publication attempt fails,  
**When** the failure is detected,  
**Then** the system must retain the report version, attempted recipients, date and time, channel, failure reason, and publishing user or process.

### AC-E6-502-12 — Prevent Duplicate Publication Events

**Given** the same report version has already been successfully published to the same recipient population through the same channel,  
**When** an equivalent publication request is submitted,  
**Then** the system must identify the prior event and prevent an indistinguishable duplicate unless authorized republication is requested.

### AC-E6-502-13 — Preserve Republication History

**Given** an authorized republication occurs,  
**When** the report is published again,  
**Then** the system must preserve the original publication event and record the new republication event separately.

### AC-E6-502-14 — Make Publication Status Available

**Given** a publication attempt has completed,  
**When** an authorized user reviews the report,  
**Then** the system must display the current publication status and relevant distribution history.

### AC-E6-502-15 — Preserve Audit Traceability

**Given** an internal publication event occurs,  
**When** the event is recorded,  
**Then** the system must preserve sufficient audit information to determine who or what published the report, which version was used, who received it, which channel was used, and what outcome occurred.
