# AC-E6-506 Archive Post-Trade Reporting Records

## Acceptance Criteria

### AC-E6-506-01 — Authorize Archival

**Given** a user requests archival of post-trade reporting records,  
**When** the request is evaluated,  
**Then** the system must verify that the user is authorized to archive the selected records.

### AC-E6-506-02 — Verify Archival Eligibility

**Given** reporting records are selected for archival,  
**When** archival begins,  
**Then** the system must verify that the applicable report versions and related reporting activities are finalized.

### AC-E6-506-03 — Prevent Archival with Open Discrepancies

**Given** unresolved reporting discrepancies remain associated with the selected records,  
**When** archival is requested,  
**Then** the system must block archival unless an authorized exception applies.

### AC-E6-506-04 — Select the Final Report Version

**Given** one or more report versions exist,  
**When** the archival package is assembled,  
**Then** the system must identify and include the applicable final approved report version.

### AC-E6-506-05 — Include Publication and Delivery History

**Given** a report has been published or delivered,  
**When** the archival package is assembled,  
**Then** the system must include the applicable publication, delivery, acknowledgement, rejection, and resubmission history.

### AC-E6-506-06 — Include Reconciliation Results

**Given** reconciliation has been performed,  
**When** the archival package is assembled,  
**Then** the system must include the applicable reconciliation results, statuses, and supporting metadata.

### AC-E6-506-07 — Include Discrepancy-Resolution Records

**Given** reporting discrepancies were identified and resolved,  
**When** the archival package is assembled,  
**Then** the system must include the discrepancy records, investigation history, resolution evidence, and approval outcomes.

### AC-E6-506-08 — Validate Archive Completeness

**Given** the archival package has been assembled,  
**When** completeness validation is performed,  
**Then** the system must verify that all required reports, evidence, histories, and metadata are present.

### AC-E6-506-09 — Block Incomplete Archival

**Given** required archival content is missing or invalid,  
**When** archival is attempted,  
**Then** the system must block completion and identify the missing or invalid records.

### AC-E6-506-10 — Apply Retention Classification

**Given** a complete archival package is ready,  
**When** the package is archived,  
**Then** the system must apply the approved retention classification and applicable retention period.

### AC-E6-506-11 — Record Archive Metadata

**Given** an archival package is created,  
**When** archival completes,  
**Then** the system must retain the archive identifier, archived records, retention classification, archival date and time, and responsible user or process.

### AC-E6-506-12 — Protect Archived Records

**Given** reporting records have been archived,  
**When** they are stored,  
**Then** the system must protect them from unauthorized alteration, replacement, or deletion.

### AC-E6-506-13 — Preserve Record Integrity

**Given** an archived reporting package is retrieved,  
**When** its integrity is evaluated,  
**Then** the system must support verification that the records remain complete and unchanged from the archived version.

### AC-E6-506-14 — Restrict Archive Access

**Given** a user requests access to archived reporting records,  
**When** access is evaluated,  
**Then** the system must verify that the user is authorized to retrieve the selected records.

### AC-E6-506-15 — Support Archive Retrieval

**Given** an authorized user searches for archived reporting records,  
**When** valid identifying criteria are provided,  
**Then** the system must make the applicable archival package retrievable.

### AC-E6-506-16 — Record Retrieval Activity

**Given** archived records are viewed, retrieved, or exported,  
**When** the access event occurs,  
**Then** the system must record the user or process, date and time, archive identifier, and access action.

### AC-E6-506-17 — Apply Legal-Hold Restrictions

**Given** archived records are subject to a legal, regulatory, audit, or investigative hold,  
**When** retention or disposition actions are evaluated,  
**Then** the system must prevent actions that conflict with the active hold.

### AC-E6-506-18 — Prevent Premature Disposition

**Given** the applicable retention period has not expired or an active hold exists,  
**When** record disposition is requested,  
**Then** the system must block disposition.

### AC-E6-506-19 — Preserve Archival History

**Given** archival, retrieval, hold, or retention events occur,  
**When** those events are recorded,  
**Then** the system must append them to the archive history without overwriting prior events.

### AC-E6-506-20 — Preserve Audit Traceability

**Given** an archival-management event occurs,  
**When** the event is recorded,  
**Then** the system must preserve sufficient audit information to determine who performed the action, which records were affected, when it occurred, what retention or hold requirements applied, and what outcome occurred.
