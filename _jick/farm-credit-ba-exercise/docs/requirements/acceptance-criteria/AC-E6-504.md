# AC-E6-504 Reconcile Post-Trade Reporting Data

## Acceptance Criteria

### AC-E6-504-01 — Authorize Reconciliation

**Given** a user requests reconciliation of a post-trade report,  
**When** the request is evaluated,  
**Then** the system must verify that the user is authorized to perform reconciliation for the selected report type.

### AC-E6-504-02 — Select a Report Version

**Given** an authorized user initiates reconciliation,  
**When** a report is selected,  
**Then** the system must identify the specific report version to be reconciled.

### AC-E6-504-03 — Retrieve Authoritative Source Records

**Given** a report version has been selected,  
**When** reconciliation begins,  
**Then** the system must retrieve the authoritative transaction, execution, allocation, confirmation, and settlement records associated with that report.

### AC-E6-504-04 — Apply Approved Matching Rules

**Given** the report and source records are available,  
**When** reconciliation is performed,  
**Then** the system must compare them using the approved field mappings, matching rules, and tolerances for the report type.

### AC-E6-504-05 — Compare Transaction Populations

**Given** the report contains transaction-level data,  
**When** reconciliation is performed,  
**Then** the system must verify that the expected transactions are present and identify missing or unexpected records.

### AC-E6-504-06 — Compare Required Field Values

**Given** matched report and source records exist,  
**When** field-level comparison is performed,  
**Then** the system must compare all required reporting fields and identify values outside approved tolerances.

### AC-E6-504-07 — Compare Totals and Summaries

**Given** the report contains totals, calculations, or summaries,  
**When** reconciliation is performed,  
**Then** the system must compare those values with totals derived from the authoritative source records.

### AC-E6-504-08 — Classify Reconciliation Results

**Given** reconciliation comparisons have completed,  
**When** the results are evaluated,  
**Then** the system must classify the report as matched, matched within tolerance, or containing discrepancies.

### AC-E6-504-09 — Record Discrepancies

**Given** one or more discrepancies are identified,  
**When** reconciliation results are recorded,  
**Then** the system must retain the affected report field or record, expected value, reported value, discrepancy type, and applicable tolerance.

### AC-E6-504-10 — Associate Discrepancies with Source Records

**Given** a discrepancy is recorded,  
**When** the reconciliation result is stored,  
**Then** the system must associate the discrepancy with the affected report version and underlying source records.

### AC-E6-504-11 — Prevent False Matched Status

**Given** unresolved discrepancies exist outside approved tolerances,  
**When** reconciliation status is assigned,  
**Then** the system must not classify the report as fully matched.

### AC-E6-504-12 — Record Reconciliation Metadata

**Given** a reconciliation run completes,  
**When** the result is stored,  
**Then** the system must retain the report version, reconciliation date and time, user or process, ruleset or definition used, and overall outcome.

### AC-E6-504-13 — Preserve Reconciliation History

**Given** a report is reconciled more than once,  
**When** a new reconciliation run completes,  
**Then** the system must preserve prior reconciliation results and record the new run separately.

### AC-E6-504-14 — Display Reconciliation Results

**Given** reconciliation results exist,  
**When** an authorized user reviews the report,  
**Then** the system must display the current reconciliation status and the associated discrepancy summary.

### AC-E6-504-15 — Support Discrepancy Resolution

**Given** unresolved discrepancies are identified,  
**When** reconciliation completes,  
**Then** the system must make those discrepancies available for investigation and resolution under US-E6-505.

### AC-E6-504-16 — Preserve Audit Traceability

**Given** a reconciliation event occurs,  
**When** the event is recorded,  
**Then** the system must preserve sufficient audit information to determine who or what performed the reconciliation, which report and source records were compared, which rules were applied, and what outcome occurred.
